# 工业相机内参（畸变）标定开发与测试指南

> 本文档记录了 `gcLogisticCar-vision-process` 项目中关于**相机内参标定 (Camera Intrinsic Calibration)** 的开发过程、算法原理、实测数据及后期优化路线。

---

## 1. 为什么要做标定？

### 1.1 问题根源

物流搬运塔吊比赛中，我们需要获取目标物料块和圆环准确的**物理坐标 (X, Y mm)**，引导塔吊机械臂进行精准抓取。但现实摄像头（尤其是广角镜头）受透镜物理工艺限制，存在以下两种主要畸变：

- **径向畸变 (Radial Distortion)**：由透镜曲率不均匀引起，直线在图像边缘表现为弯曲。桶形畸变（Barrel）是广角镜头最常见的形式，会使画面中的直线向外"膨胀"。
- **切向畸变 (Tangential Distortion)**：由透镜安装与传感器平面未严格平行引起，较小但不可忽略。

**直接后果**：如果不做去畸变，我们感知到的圆环几何中心与真实物理位置之间会产生数毫米乃至数厘米的系统性误差，严重影响抓取成功率。

**相机内参标定的唯一目的：用数学模型精确描述这块玻璃的弯曲规律，从而把弯曲的现实世界还原为平坦的欧氏空间。**

### 1.2 内参 vs 外参的核心区别

| 概念 | 描述 | 与位置/角度的关系 |
|---|---|---|
| **内参 (Intrinsic)** | 焦距、光学中心、畸变系数。只属于摄像头硬件本身。 | **完全无关** — 内参只由镜头玻璃决定，无论怎么移动和转动摄像头它都不会变。 |
| **外参 (Extrinsic)** | 摄像头在世界坐标系中的位置和姿态（R旋转矩阵 + T平移向量）。 | **强绑定** — 一旦改变安装高度或角度，外参立刻失效需重新计算。 |

> [!IMPORTANT]
> 本文所有内容仅涉及**内参标定（去畸变）**。之后将另行开发**外参标定（透视坐标映射）**。

## 2. 算法深度解析

我们采用 1998 年张正友博士提出的**平面标定法**，是目前工业界和学术界的绝对主流方案，已经被集成到 OpenCV `cv2.calibrateCamera` 中。

### 2.1 数学模型

相机将三维空间点 $P_w$ 投影到图像平面像素坐标 $p$ 的关系由以下公式描述：

**针孔投影**（理想无畸变状态）：
$$\begin{bmatrix} u \\ v \\ 1 \end{bmatrix} = \frac{1}{Z_c} \underbrace{\begin{bmatrix} f_x & 0 & c_x \\ 0 & f_y & c_y \\ 0 & 0 & 1 \end{bmatrix}}_{\text{K 内参矩阵}} \begin{bmatrix} X_c \\ Y_c \\ Z_c \end{bmatrix}$$

其中 $(f_x, f_y)$ 为焦距（单位：像素），$(c_x, c_y)$ 为图像主点（光学中心）。

**径向畸变修正**（实际镜头补偿）：
$$x' = x(1 + k_1 r^2 + k_2 r^4 + k_3 r^6)$$
$$y' = y(1 + k_1 r^2 + k_2 r^4 + k_3 r^6)$$

其中 $r^2 = x^2 + y^2$ 为归一化坐标的径向距离，$(k_1, k_2, k_3)$ 即我们要求解的畸变系数。

### 2.2 标定流程 Step-by-Step

我们将整个流程封装在 `calibration/camera_calibrator.py` 中。

#### Step 1 — 图像采集 (Capture Mode)

```
python calibration/camera_calibrator.py
```

**关键约束**（违反会导致标定精度下降）：
- 至少采集 **15 张**以上，建议 20 张。少于 10 张算法将直接报错退出。
- 棋盘格必须出现在画面的**各个角落（左上、右上、左下、右下）**。边缘畸变最严重，只在中心拍照无法建模边缘的扭曲规律。
- 棋盘格需以**不同倾斜角度**（前倾、后仰、左转、右转）出现，算法需要多角度数据来约束三维重建。
- 棋盘格打印时务必保证**平整无褶皱**！纸张翘曲会向算法输入本身就扭曲的"真值"，系统性地毒化标定结果。

**键位操作**：
| 按键 | 功能 |
|---|---|
| `s` | 当界面出现"Corners Found"时，按 `s` 保存当前帧 |
| `c` | 采集完毕，进入参数解算阶段 |
| `q` | 退出 |

#### Step 2 — 亚像素角点精细化

找到棋盘格角点后，我们使用迭代优化将角点坐标精度从像素级提升到**亚像素 (Sub-pixel)**：

```python
criteria = (cv2.TERM_CRITERIA_EPS + cv2.TERM_CRITERIA_MAX_ITER, 30, 0.001)
corners2 = cv2.cornerSubPix(gray, corners, (11, 11), (-1, -1), criteria)
```

这会在 11×11 的窗口内通过梯度下降迭代，将每个角点定位精度提升到约 0.1 像素级别，是保证最终标定精度的核心操作之一。

#### Step 3 — 解算与保存

```python
ret, mtx, dist, rvecs, tvecs = cv2.calibrateCamera(...)
np.savez("config/camera_params.npz", mtx=mtx, dist=dist)
```

输出的 `ret` 即**重投影误差 (RMS)**，单位为像素，是判断标定质量的唯一量化指标：

| RMS 值 | 质量评级 | 处理建议 |
|---|---|---|
| < 0.3 px | ⭐ 极优 | 直接投入生产使用 |
| 0.3 ~ 0.5 px | ✅ 合格 | 可以使用，达到比赛精度要求 |
| 0.5 ~ 1.0 px | ⚠️ 偏差较大 | 检查是否有褶皱，重拍部分图像 |
| > 1.0 px | ❌ 不可用 | 标定板变形或采集姿势单一，须重新标定 |

#### Step 4 — ARM 端极速去畸变 (Undistorter 类)

在树莓派上，每帧调用 `cv2.undistort` 会进行密集的反三角函数运算，CPU 占用率极高。我们的 `Undistorter` 类在**启动阶段一次性预计算映射表**，后续每帧只做纯内存搬运：

```python
# 冷启动 (仅一次，约 50ms)
mapx, mapy = cv2.initUndistortRectifyMap(K, D, None, new_mtx, (w,h), cv2.CV_16SC2)

# 运行期 (每帧，约 2ms)
undistorted = cv2.remap(frame, mapx, mapy, cv2.INTER_LINEAR)
```

## 3. 干扰因素完整分析 (FAQ)

### Q1: 更换摄像头（哪怕是同批次同型号），数据还能用吗？
**❌ 绝对不能。**

每个摄像头的透镜玻璃都有微米级的制造误差，导致畸变系数 $(k_1, k_2, k_3)$ 因个体而异，不可共享。更换硬件就必须重新完整标定一次。这是张正友标定法的基本约束。

### Q2: 摄像头安装高度改变了，内参数据失效吗？
**✅ 完全不失效。**

内参只由镜头物理属性决定，与摄像头的位置无关。只要是同一个镜头硬件，无论安装高低，畸变系数永远有效。

### Q3: 摄像头倾斜角度（俯仰角/偏航角）改变了，内参数据失效吗？
**✅ 完全不失效。**

原因同 Q2，角度是外参的范畴。内参不随摄像头的旋转而改变。

### Q4: 摄像头在比赛中被碰了一下，标定数据还有效吗？
**不确定，取决于是否影响了镜头组件本身。**

轻微碰撞（摄像头外壳被蹭到）通常不影响内参。但若撞击导致**镜头前组玻璃松动**或者 CMOS 传感器受力移位，畸变系数会发生变化，须重新标定。赛前建议额外备份一份标定文件。

### Q5: 白天和晚上的光照不同，会影响标定吗？
**不影响。**

光照只影响曝光和 ISO，不改变透镜几何。但在昏暗环境下，`cv2.findChessboardCorners` 可能因对比度不足而无法识别棋盘格，降低了可用采集帧数量，间接影响标定精度。**建议标定在与实际比赛相近的光照条件下进行。**

## 4. 内参 vs 外参的开发分工

```
视觉坐标定位完整链路：
                   ┌────────────────────────────┐
  原始视频帧  ──▶  │  内参去畸变 (Undistorter)  │  ──▶  校正帧
                   │  camera_calibrator.py        │
                   │  ✅ 与位置角度无关           │
                   └────────────────────────────┘
                                 │
                                 ▼
                   ┌────────────────────────────┐
  校正帧    ──▶   │  外参坐标映射               │  ──▶  物理XY坐标 (mm)
                   │  perspective_calibrator.py   │
                   │  ⚠️ 与高度/角度强绑定       │
                   └────────────────────────────┘
```

## 5. 后期优化方向

### 5.1 短期优化（比赛前可实施）

| 优化项 | 说明 | 优先级 |
|---|---|---|
| **多分辨率兼容** | 目前 `Undistorter` 写死了 640×480，若比赛换用 1080p 摄像头需要重新生成映射表。建议改为从参数文件动态读取分辨率。 | 高 |
| **标定图像质量过滤** | 目前所有通过角点检测的图像都会被纳入计算。若某帧虚焦或运动模糊，会拉高 RMS 误差。可加入对图像清晰度（Laplacian方差）的预筛选，自动丢弃模糊帧。 | 高 |
| **标定参数版本管理** | 将 `camera_params.npz` 文件加入版本号字段（如标定时间戳 + RMS），防止意外被覆盖或混淆不同场地的标定数据。 | 中 |

### 5.2 中期优化（有余力时考虑）

| 优化项 | 说明 |
|---|---|
| **圆形/圆点标定板** | ChArUco 或圆点阵列 (Circle Grid) 标定板比棋盘格具有更强的鲁棒性，在画面部分遮挡时仍可识别，适合现场光照复杂环境。对应 API 为 `cv2.findCirclesGrid`。 |
| **自动重标定触发机制** | 在主流程中引入"标定自检"逻辑：每次开机从 `camera_params.npz` 加载参数后，使用一张已知形状（如圆环）来评估当前的去畸变精度，若误差超过阈值则自动提示用户重新标定。 |
| **GPU/NEON 加速 remap** | 在 RK3566 等带 Mali GPU 的 ARM SoC 上，`cv2.remap` 可以通过 OpenCL 转交 GPU 执行，理论上可进一步将帧率从 30fps 提升至 60fps+。 |

### 5.3 长期优化（高级特性）

| 优化项 | 说明 |
|---|---|
| **在线自标定 (Online Self-Calibration)** | 无需棋盘格，利用比赛场景中直线结构（导轨、地砖边缘）在运行期间持续迭代更新内参。适合长时间运行后镜头因温度膨胀导致的参数漂移场景。 |
| **鱼眼相机模型支持** | 若将来升级为鱼眼（FOV>180°）工业摄像头，OpenCV 提供了专用的 `cv2.fisheye.calibrate` API，畸变模型从 $(k_1, k_2, k_3)$ 扩展为等距投影模型，精度更高。 |
