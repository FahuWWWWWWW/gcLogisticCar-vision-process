| 物品                            | 用途                   |
| ------------------------------- | ---------------------- |
| 树莓派 4B                       | 运行 Vision 程序       |


## 2. 网络连接

树莓派需要联网才能安装软件包。提供 **三种连接方式**，按推荐程度排序。

### 方式一：以太网直连 PC + ICS 共享（⭐ 最稳定）

这是实际部署时验证过的最可靠方案。原理：PC 通过 Wi-Fi 上网 → PC 把网络共享给以太网口 → Pi 通过网线获得网络。

**操作步骤**：

**第 1 步**：用网线把 Pi 和 PC 直连。

**第 2 步**：在 Windows 上开启"Internet 连接共享 (ICS)"：

1. 打开 `控制面板` → `网络和共享中心` → `更改适配器设置`
2. 找到你 PC 正在上网的网卡（通常是 WLAN / Wi-Fi），右键 → `属性`
3. 切换到 `共享` 选项卡
4. 勾选 "允许其他网络用户通过此计算机的 Internet 连接来连接"
5. 在下拉框中选择你的 `以太网` 网卡
6. 点 `确定`

> ⚠️ 开启 ICS 后，Windows 会把以太网口的 IP 固定为 `192.168.137.1`，Pi 会自动获取 `192.168.137.x` 的地址。

**第 3 步**：在 Pi 上获取 IP（需要 Pi 连接显示器或通过路由器查看），通常是 `192.168.137.xxx`。

### 方式二：连接同一路由器 / 交换机

把 Pi 和 PC 都插到同一个路由器上，Pi 会自动获取 IP。去路由器管理页面查看 Pi 的 IP。

### 方式三：手机热点（❌ 不推荐，有坑）

某些手机热点会限制局域网设备间的通信，或封锁 HTTP/HTTPS 端口（80/443），导致 `apt install` 和 `pip install` 失败。如果只能用热点，请务必先用方式一验证过环境。

### 2.1 如何找到树莓派的 IP

在你的 PC 上执行以下任一命令：

```bash
# 方法 1：ping 广播地址（Linux/macOS）
ping raspberrypi.local

# 方法 2：扫描局域网（需要安装 nmap）
nmap -sn 192.168.137.0/24

# 方法 3：查看 ARP 表
arp -a | findstr "192.168.137"
```

## 3. SSH 远程登录

### 3.1 确认 Pi 的 SSH 已开启

新版 Raspberry Pi OS 默认关闭 SSH。首次使用前，在 Pi 的 SD 卡 `boot` 分区根目录创建一个空文件名为 `ssh`（无扩展名），Pi 启动后会自动开启 SSH。

### 3.2 首次登录（使用密码）

```bash
ssh <PI_USER>@<PI_IP>
```

默认用户名通常是 `pi` 或你创建的用户名。默认密码：`raspberry`（如果没改过）。

> 💡 本项目的 Pi 实际用户为 `g0904`，IP 为 `10.66.231.190`（Wi-Fi）或 `192.168.137.222`（ICS 以太网）。

### 3.3 配置 SSH 免密登录（强烈推荐）

每次都输密码太麻烦，配置免密登录只需 3 条命令：

```bash
# 第 1 步：在 PC 上生成密钥（如果还没有）
ssh-keygen -t ed25519 -C "rpi-vision-key"
# 一路回车即可（不需要设密码短语）

# 第 2 步：把公钥复制到 Pi 上
ssh-copy-id -i ~/.ssh/id_ed25519.pub <PI_USER>@<PI_IP>
# 输入一次 Pi 的密码，之后就不用再输了

# 第 3 步：测试免密登录
ssh <PI_USER>@<PI_IP>
# 应该直接登入，不需要密码
```

### 3.4 配置 SSH 快捷别名

编辑 PC 上的 `~/.ssh/config` 文件（没有就新建），添加：

```text
Host rpi4b
    HostName 192.168.137.222
    User g0904
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 60
```

之后只需 `ssh rpi4b` 就能登录，不用记 IP。

## 4. 环境部署

### 4.1 了解项目依赖

本项目需要以下 Python 包：

| 包名                       | 用途                        | 安装方式                                      |
| -------------------------- | --------------------------- | --------------------------------------------- |
| OpenCV 4.6.0（含 contrib） | 图像处理、WeChatQRCode      | 系统预装（或 `apt install`）                  |
| NumPy                      | 数组计算                    | 随 OpenCV 安装                                |
| PyYAML                     | 读取 YAML 配置文件          | `pip install`                                 |
| PySerial                   | 串口通信                    | `pip install`                                 |
| pyzbar + libzbar0          | 条码/二维码解码（备用方案） | `apt install libzbar0` + `pip install pyzbar` |

### 4.2 步骤一：检查 Pi 当前状态

SSH 登录 Pi，执行以下命令确认基础环境：

```bash
# 查看系统信息
uname -a
# 期望输出包含: aarch64, Linux ... 6.12

# 查看 Python 版本
python3 --version
# 期望输出: Python 3.11.2

# 查看 OpenCV 是否已安装
python3 -c "import cv2; print(cv2.__version__)"
# 期望输出: 4.6.0（或其他版本号，≥4.5 即可）

# 查看磁盘空间
df -h /
# 确保有至少 2GB 剩余空间

# 查看内存
free -h
# Pi 4B 通常有 4GB 或 8GB

# 查看当前用户在哪些组（确保在 dialout 组，才能用串口）
groups
# 期望输出包含: dialout
```

### 4.3 步骤二：确认网络可用

```bash
# 测试外网连通性
ping -c 3 8.8.8.8
# 期望: 3 packets transmitted, 3 received, 0% packet loss

# 测试能否访问 Python 包仓库
curl -I https://pypi.org 2>&1 | head -1
# 期望: HTTP/2 200
```

如果网络不通，回到 [2. 网络连接](#2-网络连接) 检查。

### 4.4 步骤三：安装系统级依赖

```bash
# 更新软件包列表
sudo apt update

# 安装 libzbar0（pyzbar 的底层库）
sudo apt install -y libzbar0

# 如果 OpenCV 没装，可以这样装（通常系统已自带）
# sudo apt install -y python3-opencv
```

### 4.5 步骤四：创建 Python 虚拟环境

> ⚠️ **为什么需要虚拟环境？**  
> 新版 Raspberry Pi OS 启用了 PEP 668 保护机制，禁止用 `pip install` 直接往系统 Python 里装包（会报 `externally-managed-environment` 错误）。虚拟环境是最干净的解决方案。

```bash
# 创建虚拟环境（--system-site-packages 让 venv 能使用系统已装的 OpenCV）
python3 -m venv ~/gc_vision_venv --system-site-packages

# 激活虚拟环境
source ~/gc_vision_venv/bin/activate

# 升级 pip（可选但推荐）
pip install --upgrade pip setuptools wheel
```

> 💡 以后每次 SSH 登录 Pi 要运行 Vision 程序前，都先执行 `source ~/gc_vision_venv/bin/activate`。

### 4.6 步骤五：安装 Python 包

```bash
# 确保虚拟环境已激活（命令行前面应该有 (gc_vision_venv) 字样）
source ~/gc_vision_venv/bin/activate

# 安装项目所需的 Python 包
pip install PyYAML pyzbar pyserial
```

> 💡 `numpy` 和 `opencv` 不需要 pip 安装，因为 `--system-site-packages` 已经让 venv 能访问系统层的这两个包。

### 4.7 步骤六：验证安装

```bash
source ~/gc_vision_venv/bin/activate

# 逐个验证关键包
python3 -c "import cv2; print('OpenCV:', cv2.__version__)"
python3 -c "import numpy; print('NumPy:', numpy.__version__)"
python3 -c "import yaml; print('PyYAML:', yaml.__version__)"
python3 -c "from pyzbar import pyzbar; print('pyzbar: OK')"
python3 -c "import serial; print('PySerial:', serial.__version__)"
```

如果全部输出 OK 且没有报错，环境部署就完成了 ✅。

## 5. 代码上传

### 5.1 方式一：打包上传（一次性部署）

在 **PC 上** 的项目根目录执行：

```bash
# 第 1 步：打包整个项目（排除不需要的文件）
tar -czf /tmp/vision_code.tar.gz \
    --exclude='__pycache__' \
    --exclude='*.pyc' \
    --exclude='.git' \
    --exclude='logs/*.log' \
    --exclude='calib_images*' \
    .

# 第 2 步：上传到 Pi
scp /tmp/vision_code.tar.gz <PI_USER>@<PI_IP>:/tmp/

# 第 3 步：在 Pi 上解压
ssh <PI_USER>@<PI_IP> "mkdir -p ~/Vision && tar -xzf /tmp/vision_code.tar.gz -C ~/Vision"

# 第 4 步：清理临时文件
ssh <PI_USER>@<PI_IP> "rm /tmp/vision_code.tar.gz"
```

如果你配置了 SSH 别名，可以简化为：

```bash
tar -czf /tmp/vision_code.tar.gz --exclude='__pycache__' --exclude='*.pyc' --exclude='.git' --exclude='logs/*.log' --exclude='calib_images*' .
scp /tmp/vision_code.tar.gz rpi4b:/tmp/
ssh rpi4b "mkdir -p ~/Vision && tar -xzf /tmp/vision_code.tar.gz -C ~/Vision && rm /tmp/vision_code.tar.gz"
```

### 5.2 方式二：rsync 增量同步（日常开发推荐）

每次改了代码后，用 rsync 只传有变化的文件，快很多：

```bash
rsync -avz --delete \
    --exclude='__pycache__' \
    --exclude='*.pyc' \
    --exclude='.git' \
    --exclude='logs/' \
    --exclude='calib_images*' \
    ./ <PI_USER>@<PI_IP>:~/Vision/
```

### 5.3 确认上传成功

```bash
ssh <PI_USER>@<PI_IP> "ls -la ~/Vision/"
```

应该能看到 `main.py`、`config/`、`utils/`、`shape_detection/` 等目录和文件。

## 6. Pi 端配置适配

代码上传到 Pi 后，需要做以下适配（Windows 和 Linux 环境不同）。

### 6.1 修改串口配置

Pi 上串口设备名是 `/dev/ttyACM0` 或 `/dev/ttyUSB0`，不是 Windows 的 `COM3`。

```bash
# 在 Pi 上编辑配置文件
ssh <PI_USER>@<PI_IP> "nano ~/Vision/config/serial_config.yaml"
```

把 `port` 改成实际的设备名：

```yaml
# 改之前（Windows）
port: "COM3"

# 改之后（Linux / Pi）
port: "/dev/ttyACM0"
```

> 💡 如果不确定设备名，先插上 USB 转串口模块，然后执行 `ls /dev/tty*` 查看新增了哪个设备。常见的是 `/dev/ttyACM0`（CDC 虚拟串口）或 `/dev/ttyUSB0`（CH340/CP2102 等）。

### 6.2 确认 HEADLESS 模式可用

项目已内置 headless 支持——通过环境变量 `HEADLESS=1` 控制，在 SSH 无桌面环境下不会弹出 GUI 窗口，避免程序卡死。

查看关键代码（已在 Pi 端 `main.py` 中生效）：

```python
# main.py 第 26-27 行
headless = os.environ.get("HEADLESS", "0") == "1"

# main.py 第 172 行 —— 显示画面（仅非 headless 模式）
if not headless:
    cv2.imshow("gcLogisticCar - Main FSM", display)

# main.py 第 206 行 —— 关闭窗口（仅非 headless 模式）
if not headless:
    cv2.destroyAllWindows()
```

### 6.3 创建日志目录

```bash
ssh <PI_USER>@<PI_IP> "mkdir -p ~/Vision/logs"
```

## 7. 运行程序


在 Pi 的桌面终端中运行，不加 `HEADLESS=1`：

### 7.3 程序运行后会看到什么

正常启动后会输出类似以下日志：

```text

[INFO] 正在加载视觉算子与标定模型...
[Undistorter] 相机畸变参数加载成功，极速映射表构建完成！
```

## 9. 现场调试工具

项目内置了多个现场调试利器，帮助在没有 GUI 的 SSH 环境下快速排查问题。

### 9.1 DEBUG_SAVE 模式 — 远程看算法"看到了什么"

设置环境变量 `DEBUG_SAVE=1`，程序会在 `logs/` 目录自动保存每一帧的中间处理图像，包括：
- 颜色提取的二值化 mask（看看阈值是否合适）
- 圆环检测的轮廓叠加图（看看圆环是否被正确识别）
- QR 解码的结果标注图

```bash
# 运行 30 秒，自动收集调试图像
DEBUG_SAVE=1 HEADLESS=1 ~/gc_vision_venv/bin/python ~/Vision/main.py
# Ctrl+C 退出后查看
ls -la ~/Vision/logs/debug_*.png
```

> 💡 现场调试黄金法则：先跑一轮 `DEBUG_SAVE=1`，把图像拉回 PC 用图片查看器浏览，一秒看清问题根源。

拉回 PC 查看：
```bash
scp rpi4b:~/Vision/logs/debug_*.png ./local_debug/
```

### 9.2 命令行颜色快速标定

现场光照变化导致颜色识别不准？用一张照片快速重新标定，无需 GUI 滑条。

```bash
# 第 1 步：在 Pi 上拍一张含物料的照片（或拷贝已有图片）
# 第 2 步：计算新阈值
~/gc_vision_venv/bin/python ~/Vision/tools/quick_calibrate.py \
    --image red_sample.jpg --color red --sigma 2.5
```

## 10. 性能基准数据

以下为树莓派 4B 上实测的单模块耗时（640×480 分辨率，2026-07-12 实测）：

| 模块 | 平均耗时 | 说明 |
|------|:--------:|------|
| RingDetector（圆环检测） | 15.3 ms | 拓扑层级分析，含自适应阈值+形态学 |
| ColorExtractor inRange | 15.8 ms | LAB 转换 + CLAHE + inRange + 形态学 |
| ColorExtractor fallback | 45.1 ms | LAB 像素级距离投票（仅兜底使用） |
| WeChatQRCode 解码 | 35.1 ms | CNN 检测 + 超分模型推理 |
| Undistorter（去畸变） | ~2 ms | 预计算 remap 查表，极低开销 |
| CoordinateMapper（坐标映射） | <0.1 ms | 单次矩阵乘法 |
| **完整流水线合计** | **~111 ms** | **等效 ~9 FPS** |

> ⚠️ 45ms 的 fallback 偏慢，仅在 inRange 完全找不到目标时作为兜底策略触发。Pi 4B 的 CPU 算力是主要瓶颈。

运行性能测试：

## 11. 故障排查

### 11.1 网络相关

| 症状                         | 可能原因             | 解决方法                                                      |
| ---------------------------- | -------------------- | ------------------------------------------------------------- |
| `ping 8.8.8.8` 不通          | Pi 没获取到 IP       | 检查网线、重启 Pi 的网络：`sudo systemctl restart networking` |
| `apt update` 报 "网络不可达" | 网关配置错误         | `ip route` 查看默认网关，确认是否正确                         |
| `pip install` 报 SSL 错误    | 系统时间不对         | `sudo date -s "2026-07-12 12:00:00"` 手动设置时间             |
| 手机热点下所有下载都失败     | 热点限制了 HTTP 端口 | 改用 ICS 以太网方案（见 [2. 网络连接](#2-网络连接)）          |

### 11.2 权限相关

| 症状                     | 可能原因              | 解决方法                                             |
| ------------------------ | --------------------- | ---------------------------------------------------- |
| 串口 `Permission denied` | 用户不在 `dialout` 组 | `sudo usermod -a -G dialout $USER`，然后**重新登录** |
| `sudo` 要密码            | 用户没有 sudo 权限    | `su -` 切换到 root，或用有权限的账户                 |

### 11.3 Python / pip 相关

| 症状                                              | 可能原因                      | 解决方法                                                 |
| ------------------------------------------------- | ----------------------------- | -------------------------------------------------------- |
| `pip install` 报 "externally-managed-environment" | PEP 668 保护                  | 必须用虚拟环境，见 [4.5](#45-步骤四创建-python-虚拟环境) |
| `import cv2` 报 `ImportError`                     | OpenCV 未安装或 venv 没访问到 | 重建 venv 时加上 `--system-site-packages`                |
| `import pyzbar` 报错                              | libzbar0 未安装               | `sudo apt install -y libzbar0`                           |

### 11.4 运行时相关

| 症状                                   | 可能原因                               | 解决方法                                                             |
| -------------------------------------- | -------------------------------------- | -------------------------------------------------------------------- |
| 程序卡住不动                           | 没设置 `HEADLESS=1`，程序在等 GUI 窗口 | 加 `HEADLESS=1` 运行                                                 |
| 摄像头打不开                           | 设备号不对                             | `ls /dev/video*` 查看摄像头设备，修改 `CameraStream(src=0)` 中的数字 |
| 串口打不开 "No such file or directory" | 设备名不对或没插                       | `ls /dev/tty*` 确认设备名，修改 `serial_config.yaml`                 |
| WeChatQRCode 加载失败                  | 模型文件缺失                           | 确认 `models/wechat_qrcode/` 下有 4 个文件                           |

## 12. 开机自启（systemd 服务）

如果你希望 Pi 开机后自动运行 Vision 程序（无需手动 SSH 登录启动），可以配置 systemd 服务。

### 12.1 创建服务文件

在 Pi 上创建 `/etc/systemd/system/gc-vision.service`：

```bash
sudo nano /etc/systemd/system/gc-vision.service
```

写入以下内容：

```ini
[Unit]
Description=GC Logistic Car Vision System
After=network.target

[Service]
Type=simple
User=g0904
WorkingDirectory=/home/g0904/Vision
Environment="HEADLESS=1"
ExecStart=/home/g0904/gc_vision_venv/bin/python /home/g0904/Vision/main.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

> ⚠️ 把 `User`、`WorkingDirectory`、`ExecStart` 中的路径替换为你的实际用户名和路径。

### 12.2 启用服务

```bash
# 重新加载 systemd 配置
sudo systemctl daemon-reload

# 启动服务
sudo systemctl start gc-vision

# 查看服务状态
sudo systemctl status gc-vision

# 设置开机自动启动
sudo systemctl enable gc-vision
```

### 12.3 常用管理命令

```bash
# 查看实时日志
sudo journalctl -u gc-vision -f

# 停止服务
sudo systemctl stop gc-vision

# 重启服务
sudo systemctl restart gc-vision

# 禁用开机自启
sudo systemctl disable gc-vision
```

### 13.4 场景恢复清单

1. **联网**：网线直连 PC，开启 ICS

7. **运行验证**：`HEADLESS=1 ~/gc_vision_venv/bin/python ~/Vision/tests/headless_verify.py`
8. **启动主程序**：`HEADLESS=1 ~/gc_vision_venv/bin/python ~/Vision/main.py`
